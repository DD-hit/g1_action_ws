# 掌心中心与坐标轴：视频验证阶段

这是基于 MediaPipe 模型关键点的朝向估计，不是已经标定的相机或机器人米制位姿。尚未融合深度、相机内参或外参；`estimate_palm_pose` 的米制融合入口仍未实现。

## 坐标约定

- 原点：手腕与四个指根中心的中点，避免指尖弯曲直接移动原点。
- `+Y`：从手腕朝四个指根中心，投影至拟合掌面。
- `+Z`：掌面外法向。采用腕点及指根拟合平面，以稳定的模型左右手标签和点序确定法向符号。
- `+X = Y × Z`，重新正交化，确保旋转矩阵属于 SO(3)，行列式为正一。
- 紫色 `thumb`：拇指 MCP 到拇指尖的独立方向，不强制与 `+X` 同向。

法向符号按当前视频和未镜像的模型输出约定核对，配置位于 `handshake.yaml` 的 `perception.palm_frame.normal_sign_by_label`。后续换相机、改变镜像设置或接入真实 3D 坐标时，需要重新核对该约定。模型左右手分类本身不是人工真值。

## 跟踪与不确定帧

新轨迹须连续积累分类结果，达到确认条件后固定该轨迹的左右属性。短暂原始标签反复只记录不一致，不翻转已确认的法向；目标失踪超时后重新建立轨迹。当前按图像掌心位置关联，尚不支持任意多人交叉场景的身份保证。

旋转用极分解投影回 SO(3) 后平滑。突变先不输出有效坐标系，连续几次候选一致后才重捕获。掌面退化、明显不共面或分类待确认时，输出 `valid: false`，不把旧姿态冒充为当前有效观测。

## 使用

新视频仍使用原入口，配置开启后会同时绘制坐标轴：

```bash
bash scripts/g1.sh handshake-video /absolute/path/video.MOV
```

已有关键点结果可直接回放，无需重复 GPU 推理或解码原始 4K 视频：

```bash
bash scripts/g1.sh handshake-axes \
  data/handshake/reviews/IMG_2044_jetson_gpu \
  --output data/handshake/reviews/IMG_2044_palm_axes
```

输入目录包含 `annotated.mp4` 和逐帧对应的 `landmarks.jsonl`。输出 `palm_axes.mp4`、`palm_frames.jsonl`、`summary.json`、`preview.jpg`，源帧索引和时间戳保持不变。已有非空输出目录不会被覆盖。

红、绿、蓝分别表示 `X`、`Y`、`Z`，白点是掌心中心，紫色为拇指方向。近乎垂直画面的轴用圆点表示朝向观察者、叉号表示远离观察者。投影仅用于显示，不代替标定相机的透视投影；`palm/back/edge` 也是模型估计的相对观察方向。

`rotation` 是经过检查及平滑的旋转矩阵，列依次为 X/Y/Z；`rotation_raw` 是未平滑估计。模型坐标原点为 `origin_model`，图像归一化中心为 `center_image`。不能将 `origin_model` 当作机器人目标平移量。

## 验证范围

9 项测试覆盖左右手的右手坐标系、镜像后法向、指尖弯曲、刚体变换等变性、退化几何、短暂标签翻转、突变重捕获、失踪后重新确认、平滑后正交性。

统计中的 raw 角度包含被拒绝观测，filtered 角度仅统计常规跟踪，不包含重捕获，两个 P95 不能直接当作同口径准确率对比。当前结果仍需人工观看翻掌/侧掌画面；没有姿态真值，未量化绝对角度准确率。
