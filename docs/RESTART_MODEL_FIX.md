# 重启后到预备点超时：模型资源迁移修复

## 已确认的问题

驱动冷启动仍加载 package://ele_elevator 下的网格；旧包已经删除。真实失败日志出现大量 Package [ele_elevator] does not exist / Error retrieving file，规划模型中的 26 处网格碰撞引用无法加载。当前模型共有 38 处碰撞几何。

第一次失败的右肘目标约 -0.319675 rad，超时时实测约 0.709850 rad，差约 1.029525 rad，明显超过 0.035 rad 到位容差，不能当作误差轻微而放宽到位条件。

重启会重新构建 MoveIt 模型，因此必须在不依赖旧包的干净环境中检查资源和实际加载形状，不能只看模拟执行是否成功。

## 修改

- 主模型及备用 hull 模型的各 61 处资源引用从 ele_elevator 迁至 g1_actions。
- XML 对比确认原有几何、变换、关节轴、关节限位和惯性数值均保持不变。
- 驱动在加载 MoveIt 模型后逐 link 比较 URDF 声明与实际加载的碰撞几何数；不完整则拒绝初始化，并指出 link、declared、loaded。
- 正常初始化记录 CollisionGeometryLoaded，已确认 declared=38 loaded=38。
- 增加资源解析、故意缺失碰撞网格的初始化拒绝测试，以及本次上/下行故障输入的回放。
- 未改变速度、关节控制增益、到位容差、完成超时或碰撞禁用规则。原驱动构建和启动脚本未改变。

## 验证

- Mac pre-commit：驱动规划器改动通过。
- 两个 URDF 均通过 cad urdf validate，无错误或警告，各 61 处网格均能解析。
- 主模型 check_urdf 通过，CAD 视图和快照已检查；未重新逐关节扫限位，本次没有改变空间或关节定义。
- 5 组 CTest、18 项统一接口测试通过。
- 3 项模型资源/启动测试通过；缺失一个碰撞网格时拒绝初始化。
- 本次上/下行故障输入和原基准上下行，共 4 个动作均通过完整假 SDK 回放并释放控制权。
- 对故障输入，原 43 个种子的两个 IK 解均被完整模型判为碰撞；扩展种子找到其他合法姿态。

模拟 SDK 不代表真实电机跟踪验证。以上已确认模型加载缺陷并验证修复；真实机器人是否仍存在其他跟踪问题，需要现场复测。没有发送真机运动指令；原常驻服务已关闭，测试进程均应退出后再由用户启动服务。
